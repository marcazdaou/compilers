# j-- Compiler

[![tests](https://github.com/marcazdaou/compilers/actions/workflows/tests.yml/badge.svg)](https://github.com/marcazdaou/compilers/actions/workflows/tests.yml)

A compiler for **j--**, a subset of Java, that produces **JVM bytecode** (`.class` files that run on the standard
`java` command). Starting from the teaching compiler that accompanies *Introduction to Compiler Construction in a
Java World* (Campbell, Iyer and Akbal-Delibaş), I extended the language with new types, operators and control flow,
through every stage of the compiler: scanner, parser (hand-written and JavaCC), type checking and code generation.

The test suite checks the scanner and parser against expected output, and checks code generation **against `javac`
itself**: every test program is compiled by both compilers, run on the JVM, and must print exactly the same output.

## What I added

| Area | Features |
|---|---|
| **Types** | `long` and `double`: literals (`42L`, `3.14`, `1e3`), arithmetic, comparisons, locals, fields, parameters and return values (two-slot locals) |
| **Operators** | `-` `/` `%` unary `+`; comparisons `<` `>=` `!=`; logical `\|\|` (short-circuit); `++` / `--` (prefix and postfix); compound assignment `-=` `*=` `/=` `%=`; conditional `a ? b : c` |
| **Statements** | `do`-`while`, `for`, `break`, `continue`, and `switch` with fall-through and `default` |
| **Code generation** | `switch` compiles to **TABLESWITCH** or **LOOKUPSWITCH**, chosen by comparing their estimated space and time cost (the same heuristic `javac` uses); long/double comparisons use `LCMP` / `DCMPL` / `DCMPG` so comparisons with `NaN` are false, as in Java |
| **Front ends** | Each feature in both the hand-written recursive-descent parser and the JavaCC grammar (`src/jminusminus/j--.jj`) |

Example: a dense `switch` (cases 1–5) and a sparse one (cases 1, 1000, 1000000) from
[`tests/features/SwitchTest.java`](tests/features/SwitchTest.java), as compiled by j-- (`javap -c`):

```
tableswitch   { // 1 to 5              lookupswitch  { // 3
          1: 40                                  1: 36
          2: 46                               1000: 42
          3: 52                            1000000: 48
          4: 58                            default: 54
          5: 64                       }
    default: 70
}
```

## Testing

```bash
ant                       # build lib/j--.jar (Java 21 + Apache Ant)
python tests/run_tests.py # 82 checks
```

| Check | What it verifies | Count |
|---|---|---|
| Golden files | Scanner tokens (`-t`) and parse trees (`-p`) match the expected `.tokens` / `.ast` files, for both front ends | 34 |
| Differential | Program compiled by j-- and by `javac`, both run with the same arguments: identical output required | 31 |
| Rejection | Programs with type errors produce a compile error, not a crash, and no class file | 5 |
| Bytecode | Expected instructions appear in the generated code (`tableswitch`, `lookupswitch`, `lmul`, `ddiv`, `lcmp`, `dcmpg`) | 6 |

The suite runs on every push with GitHub Actions.

**Bugs the tests caught and I fixed:**
- **Conditional expression** evaluated its condition twice, leaving an extra value on the operand stack:
  `c += x > 2 ? 1 : 0` computed the wrong result, and a conditional with `String` operands failed JVM verification.
- **`||`** was generated with the logic of `&&`, so `false || true` evaluated to `false`.
- **Comparisons on `long` and `double`** used the `int` instructions (invalid bytecode), and `!=` on `long` gave
  wrong answers; all six comparisons now go through one shared helper.
- **Type errors** such as `"42" / 5` crashed the compiler with a `NullPointerException` instead of reporting an error.
- **Constructors** were wrongly required to contain a `return` statement, and constructor code generation crashed
  because the defining class was never recorded.

## Run it

```bash
ant
./bin/j-- tests/features/SwitchTest.java    # writes SwitchTest.class (bin\j--.bat on Windows)
java SwitchTest
```

Debug options: `-t` prints the tokens, `-p` the abstract syntax tree (JSON), `-pa` the tree after pre-analysis and
`-a` the tree after type checking. `./bin/javaccj--` runs the compiler with the JavaCC front end, and
`javap -c SwitchTest` shows the generated bytecode.

## Not supported

Interfaces and exception handling (`try` / `catch` / `throw`) are part of the j-- specification but are not
implemented here; the compiler reports a syntax error for them. `++` and `--` work on `int` only (use `+= 1L` for `long`).

## Repository layout

```

tests/features/      Feature tests written for this project
tests/*.java         Example programs from the original j-- distribution
codegen/ simpleops/  Programs exercising the added features (and *Fail.java programs that must be rejected)

langspec.txt         The j-- language specification
build.xml            Ant build
```
